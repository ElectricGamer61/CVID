# Content engine — standing instructions

This folder is Dennis's **NoCrapDiet content engine** (the only active brand; other cartridges are dormant in `BRANDS.md`). Funnel-shaped system: `00-MAP` (overview, laws, loop) → `01-STOP` (hooks) → `02-HOLD` (retention) → `03-TRUST` (proof/voice) → `04-CAPTURE` (email capture) → `05-SELL` (offer). Support: `BRANDS.md` (cartridges + Growth Log), `RUN.md` (the live loop + prompts), `scripts/RULES.md` (**canonical script format — overrides everything on script output**), `LONGFORM.md` (YouTube, dormant until first long-form).

## PRIME DIRECTIVE — ship posts, don't grow the OS
The engine's output is **filmed reels and captured emails**, not better docs. Before any engine-improvement work, ask: does this change what gets filmed or posted this week? If not, it waits. New frameworks/transcripts only get banked if they beat something already in the files — the bar is replacement, not addition.

## DO THIS FIRST — every time, no exceptions
Before generating **any hook, voiceover script, film brief, or video idea**, READ the relevant engine files so the output is grounded in the system, not generic:
- **Always:** `00-MAP.md`, `01-STOP.md`, `02-HOLD.md`, `03-TRUST.md`, `BRANDS.md` (NoCrapDiet cartridge + Growth Log), `RUN.md`, `scripts/RULES.md`.
- **Add** `04-CAPTURE.md` / `05-SELL.md` for any `invitation` (magnet/offer-centered) piece, and `LONGFORM.md` for any YouTube long-form.

Then confirm you read them by opening your output with the winning format / the specific rule you're applying (e.g. "costume reframe, shock in frame one, real label read on screen"). If you can't reference the system, you didn't read it — stop and read first.

## Dennis's live workflow (the only loop)
1. Dennis asks for reel concepts ("give me food lies") → return a **FILM BRIEF**: angle + exact product + verified numbers + shot list, picked via 360-mapping + shock score, in the validated **costume format** (RUN.md).
2. He batch-films ~6–10 raw reels on one grocery run.
3. Claude writes **voiceover scripts to that footage** in the exact `scripts/RULES.md` format — one beat per clip, saved to `scripts/`. **Never save writing outputs into cvideo** — cvideo is Dennis's production + metrics workspace (editing + performance capture), not a writing folder.
4. He pulls the script into cvideo, voiceovers, edits, posts (~3/day). cvideo captures each post's performance and pushes it to the **tracker Google Sheet** automatically.
5. Sunday: MEASURE (RUN.md) — Claude reads the tracker Google Sheet, ranks, banks winners to the Growth Log, prunes, one craft note.

## Non-negotiables when writing
- NoCrapDiet voice: blunt, been-lied-to, short punchy lines.
- **Numbers: verified or absent. NO `[X]` placeholders, ever.** Verify the real label figure before writing it, or write the line with no number ("more sugar than a glazed donut"). Never guess. (RULES.md rule 1 — this overrides any older "[X]" convention.)
- **Every CTA drives to nocrapdiet.com** (the free guide). Rotate the mechanism (comment SWAP / DM SWAP / link in bio / say the site), never the destination. Follow/save = secondary only. (RULES.md + 04-CAPTURE.)
- **Muted-first:** ~80% watch with sound off — on-screen text + label visuals must carry the whole message alone. Run the mute test on every script.
- **No em-dashes in hooks** (reads as AI). One idea per hook, topic clear in sentence one.
- Script output = clean RULES.md format only. Brainstorm hooks internally; only the single winner ships.

## How to grow the engine
Improve the file that owns that funnel stage — never a new file per addition. Map a new framework against what's here (most of it already exists under other names); write only the genuinely-new ~20%, route it to one home, say what you discarded — and only if it clears the Prime Directive bar.

## Archive every input — no exceptions
Whenever Dennis sends a video transcript (or doc) for engine improvement, archive it in `_video-inputs/`:
1. Save the raw transcript + title + URL to `_video-inputs/raw-transcripts/NN-short-title.md`.
2. After extracting/routing, log it in `_video-inputs/summaries/SUMMARIES.md`: summary · key points · what was added to which file · what was discarded and why.
This is the audit trail — it stops us re-adding things already banked.
